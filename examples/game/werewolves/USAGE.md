## 核心改进点

### ✅ 数据收集修复
- **原问题**: `alive_players` 始终为空
- **现状态**: 正确追踪玩家生死
- **验证点**: 查看 "[记忆]" 日志

### ✅ 结构化输出保护
- **原问题**: `reach_agreement` 字段缺失导致崩溃
- **现状态**: 自动补充默认值
- **验证点**: 狼人讨论阶段无错误

### ✅ 学习触发优化
- **原问题**: 每次 observe 都触发，产生大量日志
- **现状态**: 仅在关键事件时触发
- **验证点**: 看到 "⏭️ 跳过" 日志

### ✅ 调试日志增强
- **原问题**: 无法观察学习过程
- **现状态**: emoji标记的结构化日志
- **验证点**: 清晰的事件追踪

## 日志符号说明

| Emoji | 含义 | 触发时机 |
|-------|------|---------|
| 🧠 | 学习模块执行 | 游戏状态有效时 |
| ⚡ | 关键事件检测 | 死亡/质疑/投票 |
| ⚠️ | 警告信息 | 数据异常时 |
| 👁️ | 对手分析 | 策略识别变化 |
| 📚 | 经验检索 | 找到历史案例 |
| 💡 | 策略推荐 | 生成决策建议 |
| ⏭️ | 跳过执行 | 数据不足时 |

## 故障排查

### 问题1: 仍然看到 "alive_players 列表为空" 警告
**原因**: 游戏开始时还没初始化
**解决**: 正常现象，等待第一条 "the players are:" 消息

### 问题2: 大量 "跳过学习模块" 日志
**原因**: 游戏未正式开始或已结束
**解决**: 正常行为，确保游戏正在进行中

### 问题3: 结构化输出警告频繁出现
**原因**: LLM模型输出不稳定
**解决**: 
1. 检查API配额
2. 尝试降低并发度
3. 更换更稳定的模型

### 问题4: 学习模块从未执行
**检查**:
1. `alive_count > 0`
2. `current_round > 0`
3. `_is_critical_event()` 能识别事件

## 高级配置

### 调整学习触发阈值
编辑 `agent.py`:
```python
# 更早触发经验检索（默认3局）
if alive_count > 0 and self.player_memory.total_games >= 2:  # 改为2

# 更早触发策略推荐（默认2局）
if alive_count > 0 and self.player_memory.total_games >= 1:  # 改为1
```

### 添加自定义关键事件
编辑 `_is_critical_event()`:
```python
critical_keywords = [
    # 原有关键词...
    '自爆', 'reveal', '查验',  # 添加新关键词
]
```

### 调整日志详细度

```python
print(...)  # 改为 logging.debug(...)

# 增加日志（调试）
在每个学习模块调用前后添加 print()
```
